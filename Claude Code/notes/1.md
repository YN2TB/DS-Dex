### Start
- Ask about the codebase
	- "How is `file` used?"
	- "How do I make a new `function`?"
	- "How does `function` take so many arguments?"
	- ...

### Edit code
- Use tools to get things done (there are built in tools)
- Steer Claude to use tools your way
	- "Propose a few fixes for issue `issue`, then implement the one I choose"
	- "commit, push, pr"
	- ...

### Plug in you own tools
- Tell Claude about your bash, MCP, etc. tools

### Common workflows
- Explore > plan > comfirm > code > commit
	- "Figure out the root cause for the `issue`, then propose a few fixes. Let me choose an approach before you code. ultrathink"
- Write tests > commit > code > iterate > commit
- Write code > screenshot result > iterate

### Give Claude context
- More context = better performance
	- CLAUDE.md in .claude folder or enterprise root shared between all projects
	- CLAUDE.md in project root for a project
	- CLAUDE.local.md for your self
Contain things you should know in order to work in a codebase
Keep it short, too long will backfire
- Pull in context on demand
	- .md files (for specific issues,...) can be put in `commands` folder in .claude folder of project root or the system .claude folder
	- .md files can also be put in `commands` folder inside a subfolder
	This create a command `/user:<command directory>` or `/project:<command directory>` depends on where you store them, use to pull context on demand

### Work with your team
- Share permissions, memory, and MCP servers with your team

### Keybindings
- `Shift+Tab` to auto accept edits
- `#` to create memory
- `!` to enter bash mode
- `@` to add a file/folder to context
- `Esc` to cancel
- Double `Esc` to jump back in history, `--resume` to resume
- `Ctrl+R` to verbose output
- `/vibe`
