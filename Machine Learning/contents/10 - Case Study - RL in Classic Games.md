## Part 1 — Game Theory

> **What is the optimal policy $\pi^i$ for the $i$th player?**
> - If all other players fix their policies $\pi^{-i}$, the **best response** $\pi^i_*(\pi^{-i})$ is the optimal policy against those policies
> - A **Nash equilibrium** is a joint policy for all players such that $\pi^i = \pi^i_*(\pi^{-i})$ — **every player's policy is a best response**, so **no player would choose to deviate**

> - **Best response is the solution to a single-agent RL problem** — other players become part of the environment, **the game is reduced to an MDP**, and the best response is that MDP's optimal policy
> - **Nash equilibrium is a fixed-point of self-play RL** — experience is generated by playing games between agents, each learning a best response *(truncated)*

**This is the conceptual bridge of the lecture.** Fixing the opponents turns a game into an MDP, so all of Lectures 1–9 applies unchanged. Self-play then iterates that: each agent improves against the others, and the fixed point of that process is the Nash equilibrium.

**Two-player zero-sum games** — two alternating players (white and black) with **equal and opposite rewards**, $R^1 + R^2 = 0$. Two methods for finding Nash equilibria: **game tree search (planning)** and **self-play reinforcement learning**.

**Perfect vs imperfect information:**
- **Perfect information (Markov) games** are fully observed — Chess, Checkers, Othello, Backgammon, Go
- **Imperfect information games** are partially observed — Scrabble, Poker

## Part 2 — Minimax Search

> A value function defines the expected total reward given joint policies $\pi = \langle\pi^1,\pi^2\rangle$: $v_\pi(s) = \mathbb{E}_\pi[G_t\mid S_t = s]$
>
> A **minimax value function** maximises white's expected return while minimising black's:
> $$v_*(s) = \max_{\pi^1}\min_{\pi^2}v_\pi(s)$$
> **There is a unique minimax value function** *(truncated)*.

> Minimax values can be found by **depth-first game-tree search**, introduced by **Claude Shannon** in *Programming a Computer for Playing Chess*. **Ran on paper!**

The worked example alternates max and min layers over leaf values $+5, +9, -6, -4, -4, -2, +7, +3$, backing up to $+7, -2, +9, -4$ at the min layer, then $-2, -4$, then $-2$ at the root.

### Value function approximation in search

> **The search tree grows exponentially — impractical to search to the end of the game.** Instead use a value function approximator $v(s,\mathbf{w}) \approx v_*(s)$, **a.k.a. evaluation function or heuristic function**, to estimate the minimax value at **leaf nodes**. Minimax search is run to a **fixed depth** with respect to leaf values.

**Binary-linear value function** — a binary feature vector $\mathbf{x}(s)$ (e.g. one feature per piece) and weights $\mathbf{w}$ (e.g. the value of each piece); the position is evaluated by summing the weights of active features:
$$v(s,\mathbf{w}) = \mathbf{x}(s)\cdot\mathbf{w}$$

This is exactly the linear function approximation of [[06 - Value Function Approximation]], applied at the leaves of a search tree.

### Deep Blue and Chinook

**Deep Blue:**
> **Knowledge** — 8000 handcrafted chess features · binary-linear value function · **weights largely hand-tuned by human experts**
> **Search** — high-performance parallel alpha-beta · **480 special-purpose VLSI chess processors** · **200 million positions/second** · **16–40 ply lookahead**
> **Results** — defeated Garry Kasparov **4–2 (1997)**, the most watched event in internet *(history)*

**Chinook:**
> **Knowledge** — binary-linear value function · 21 knowledge-based features (position, mobility, …) × 4 game phases
> **Search** — alpha-beta plus **retrograde analysis**: search *backward* from won positions, storing all winning positions in lookup tables, so it **plays perfectly from the last $n$ checkers**
> **Results** — defeated Marion Tinsley in the 1994 world championship

**Note what both have in common: hand-tuned weights.** The rest of the lecture asks whether RL can learn them instead.

## Part 3 — Self-Play Reinforcement Learning

Apply value-based RL to games of self-play — the same three targets as [[04 - Model-Free Prediction]]:

$$\text{MC: } \Delta\mathbf{w} = \alpha(G_t - v(S_t,\mathbf{w}))\nabla_\mathbf{w}v(S_t,\mathbf{w})$$
$$\text{TD(0): } \Delta\mathbf{w} = \alpha(v(S_{t+1},\mathbf{w}) - v(S_t,\mathbf{w}))\nabla_\mathbf{w}v(S_t,\mathbf{w})$$
$$\text{TD(λ): } \Delta\mathbf{w} = \alpha(G^\lambda_t - v(S_t,\mathbf{w}))\nabla_\mathbf{w}v(S_t,\mathbf{w})$$

### Afterstates

> **For deterministic games it is sufficient to estimate $v_*(s)$**, because we can efficiently evaluate the **afterstate**:
> $$q_*(s,a) = v_*(\text{succ}(s,a))$$
> The rules define the successor state $\text{succ}(s,a)$, and actions are selected by min/maximising the afterstate value:
> $$A_t = \arg\max_a v_*(\text{succ}(S_t,a)) \text{ for white} \qquad A_t = \arg\min_a v_*(\text{succ}(S_t,a)) \text{ for black}$$

**This reverses the argument of [[05 - Model-Free Control]]**, which insisted control needs $Q$ because improving from $V$ requires a model. In games **you have the model** — the rules tell you exactly where each move leads — so $V$ suffices, and the table is $|\mathcal{A}|$ times smaller.

### Logistello (Othello)

> **Logistello created its own features.** Start with raw inputs ("black stone at C1?") and **construct new features by conjunction/disjunction**, creating **1.5 million features** in different configurations, then a binary-linear value function over them.
>
> **Logistello used generalised policy iteration:** generate a batch of self-play games from the current policy → **evaluate by Monte-Carlo (regress to outcomes)** → greedy policy improvement.
>
> **Result: defeated World Champion Takeshi Murakami 6–0.**

GPI from [[03 - Planning by Dynamic Programming]], with MC evaluation from [[04 - Model-Free Prediction]], at world-champion level.

### TD-Gammon (Backgammon)

> - Initialised with **random weights**
> - Trained by **games of self-play**
> - Using **non-linear** temporal-difference learning with a neural network:
> $$\delta_t = v(S_{t+1},\mathbf{w}) - v(S_t,\mathbf{w}) \qquad \Delta\mathbf{w} = \alpha\delta_t\nabla_\mathbf{w}v(S_t,\mathbf{w})$$
> - **Greedy policy improvement (no exploration)**
> - **The algorithm always converged in practice. Not true for other games.**

> **Results:**
> - **Zero expert knowledge ⇒ strong intermediate play**
> - Hand-crafted features ⇒ advanced level (1991)
> - 2-ply search ⇒ strong master play (1993)
> - **3-ply search ⇒ superhuman play (1998)**
> - **Defeated world champion Luigi Villa 7–1 (1992)**

**Two things are remarkable.** First, **no exploration** — pure greedy self-play, contradicting everything in [[09 - Exploration and Exploitation]]. It works because backgammon's **dice rolls provide stochasticity for free**: the environment explores on the agent's behalf. Second, **it converged despite the deadly triad** (non-linear approximation + bootstrapping + off-policy-ish self-play) — which [[06 - Value Function Approximation]] says can diverge. The lecture flags this explicitly: *"not true for other games."*

## Part 4 — Combining RL and Minimax Search

> **Simple TD** — update the value towards the successor value. Famously applied to backgammon by Tesauro; **simple greedy action selection sufficed during training**. *"…unfortunately, not so successful everywhere (e.g. Chess)."*

> **Simple TD results:** Othello superhuman (Logistello) · Backgammon superhuman (TD-Gammon) · **Chess poor** · **Checkers poor**.
>
> **In chess, tactics seem necessary to find signal in a position** — e.g. hard to find checkmates without search.
>
> **Can we learn directly from minimax search values?**

**This is the lecture's central question**, and the three answers below are three increasingly aggressive ways of saying yes.

### TD Root

> **Update the value towards the successor *search* value.** The search value is computed at the root position:
> $$v_+(S_t,\mathbf{w}) = \underset{s\in\text{leaves}(S_t)}{\text{minimax}}\; v(s,\mathbf{w})$$
> The value function is backed up from the search value at the next state:
> $$v(S_t,\mathbf{w}) \leftarrow v_+(S_{t+1},\mathbf{w}) = v(l_+(S_{t+1}),\mathbf{w})$$
> where $l_+(s)$ is the leaf node achieving the minimax value from $s$.

> **TD Root in Checkers: Samuel's player** — the **first ever TD learning algorithm (Samuel 1959)**, applied to a checkers program that learned by self-play and **defeated an amateur human player**. *"Also used other ideas we might now consider strange."*

### TD Leaf

> **Update the *search* value towards the successor search value.** Search values are computed at both the current and next step:
> $$v_+(S_t,\mathbf{w}) \leftarrow v_+(S_{t+1},\mathbf{w}) \;\Longrightarrow\; v(l_+(S_t),\mathbf{w}) \leftarrow v(l_+(S_{t+1}),\mathbf{w})$$

**The difference from TD Root:** TD Root updates the *root's* value from a search; **TD Leaf updates the leaf that the search actually relied on.** Since the leaf is what determined the root's value, that is where the error belongs.

**KnightCap (chess):**
> Trained **against an expert opponent**, starting from **standard piece values only**, learning weights by TD leaf with alpha-beta search.
> **Achieved master level play after a small number of games.**
> **But: was not effective in self-play. Was not effective without starting** *(from good initial weights)*.

**Chinook (checkers):** the original used hand-tuned weights; a later version was trained by **self-play using TD leaf**, except material weights which were kept fixed. **Self-play weights performed ≥ hand-tuned weights** — learning at superhuman level.

### TreeStrap

> **Update search values towards *deeper* search values.** The minimax search value is computed at **all** nodes $s\in\text{nodes}(S_t)$, and the value is backed up **at the same step, for all nodes**:
> $$v(s,\mathbf{w}) \leftarrow v_+(s,\mathbf{w}) \;\Longrightarrow\; v(s,\mathbf{w}) \leftarrow v(l_+(s),\mathbf{w})$$

**TreeStrap extracts far more signal per game.** TD Root and TD Leaf produce one update per move; TreeStrap produces an update at **every node of the search tree**, learning from the entire computation rather than just its result.

**Meep (chess):**
> Binary linear value function with **2000 features**, starting from **random initial weights (no prior knowledge)**, weights adjusted by TreeStrap.
> - **Won 13/15 vs. international masters**
> - **Effective in self-play**
> - **Effective from random initial weights**

**Those last two bullets are the point** — they are exactly the two things KnightCap could *not* do.

### Simulation-based search

> **Self-play reinforcement learning can replace search.** Simulate games of self-play from the root state $S_t$ and apply RL to the simulated experience: **Monte-Carlo Control ⇒ Monte-Carlo Tree Search**.
>
> **The most effective variant is UCT** — balance exploration/exploitation in each node using **UCB**. **Self-play UCT converges on the min**(imax values).

**UCT = MCTS ([[08 - Integrating Learning and Planning]]) + UCB ([[09 - Exploration and Exploitation]])** — the two previous lectures combined into one algorithm.

> **MCTS is the best performing method in many challenging games** — Go, Hex, Lines of Action, Amazons. **In many games simple Monte-Carlo search is enough** — Scrabble, Backgammon.

**Maven (Scrabble):**
> **Learning** — evaluates moves by *score + $v(\text{rack})$*, a binary-linear value function of the rack using one-, two- and three-letter features (`Q??????`, `QU?????`, `III????`), **learnt by Monte-Carlo policy iteration (cf. Logistello)**.
> **Search** — **roll out moves by imagining $n$ steps of self-play**, then evaluate the resulting position.
> **Results** — beat world champion **Adam Logan 9–5**; analysis showed Maven had an **error rate of 3 points per game**.

## Part 5 — Imperfect-Information Games

> **Players have different information states and therefore separate search trees.** There is **one node per information state**, summarising what a player knows (e.g. the cards they have seen). **Many real states may share the same information state**, and states may be further aggregated by similarity.

**This is the POMDP structure of [[01 - Introduction to Reinforcement Learning]]** — and the reason stochastic policies are required ([[07 - Policy Gradient Methods]]): a deterministic poker strategy is exploitable.

> **Solution methods:**
> - **Iterative forward-search** — e.g. **counterfactual regret minimization**, giving *"perfect" play in heads-up limit Hold'em*
> - **Self-play reinforcement learning** — e.g. **Smooth UCT**, which won **3 silver medals** in two- and three-player limit Hold'em

**Smooth UCT:**
> Apply MCTS to the information-state game tree — a variant of UCT **inspired by game-theoretic Fictitious Play**. **Agents learn against and respond to opponents' *average* behaviour**, extracting the average strategy from action counts:
> $$\pi_{avg}(a\mid s) = \frac{N(s,a)}{N(s)}$$
> At each node, pick actions according to $A \sim \text{UCT}(S)$ with some probability, and $\pi_{avg}$ otherwise.

**Responding to the *average* opponent rather than the current one is what stabilises self-play.** Best-responding to a moving target can cycle forever (rock beats scissors beats paper beats rock); averaging damps the oscillation and converges toward equilibrium.

## ✏️ Exercises

**1.** Explain how a game reduces to an MDP, and why Nash equilibrium is the fixed point of self-play RL.

> [!example]- Solution
> **The reduction:** *"best response is the solution to a single-agent RL problem — other players become part of the environment, the game is reduced to an MDP."*
>
> If the opponents' policies $\pi^{-i}$ are **fixed**, then from player $i$'s perspective their behaviour is just part of the transition dynamics. When I play $a$, the environment responds with the opponent's move and then a new position — indistinguishable from a stochastic transition $\mathcal{P}^a_{ss'}$. **Everything from Lectures 1–9 applies unchanged**, and the best response is that MDP's optimal policy.
>
> **Why this is not the whole story:** the opponents are not fixed. As I improve, they improve, so **the MDP I am solving keeps changing** — the environment is non-stationary in a way no single-agent method assumes.
>
> **Self-play is the iteration that handles this.** Each agent continually best-responds to the others' current policies. The **fixed point** of that process is the state where **every agent's policy is already a best response to all the others** — which is precisely the definition of a **Nash equilibrium**: *"no player would choose to deviate."*
>
> **The structural parallel with GPI is exact.** Policy iteration ([[03 - Planning by Dynamic Programming]]) alternates evaluation and improvement until improvement stops, and stopping means the Bellman optimality equation holds. Self-play alternates best-responses until nobody wants to change, and stopping means the Nash condition holds. **Both are fixed-point iterations, and in both cases the fixed point is the solution.**
>
> **The convergence caveat, though, is real.** Policy iteration provably converges (monotone improvement, finite policy space). Self-play need not — best-responding to a moving target can **cycle** indefinitely, as in rock-paper-scissors where each pure strategy beats the last. **This is exactly why Smooth UCT responds to the opponent's *average* behaviour** rather than its current behaviour: averaging damps the oscillation. In zero-sum perfect-information games the minimax structure gives convergence guarantees that general-sum games lack.

**2.** Explain afterstates and why deterministic games can use $V$ rather than $Q$, contradicting [[05 - Model-Free Control]].

> [!example]- Solution
> **The claim in [[05 - Model-Free Control]]** was that model-free control must learn $Q$, because greedy improvement from $V$ requires a model:
> $$\pi'(s) = \arg\max_a\left(\mathcal{R}^a_s + \gamma\sum_{s'}\mathcal{P}^a_{ss'}V(s')\right)$$
>
> **In a deterministic game the model is free.** The rules define $\text{succ}(s,a)$ exactly — if I play Nf3, I know precisely which position results. So the sum collapses to a single term and the lookahead becomes trivial:
> $$q_*(s,a) = v_*(\text{succ}(s,a)) \qquad A_t = \arg\max_a v_*(\text{succ}(S_t,a))$$
>
> **The afterstate is the position *after* my move but *before* the opponent's.** Evaluating it requires only $V$.
>
> **Why this is a real advantage, not just a technicality — three reasons:**
>
> **1. The table is $|\mathcal{A}|$ times smaller.** In chess with ~35 legal moves, $Q$ needs 35× the parameters of $V$ for the same coverage.
>
> **2. It generalises better, and this is the deeper point.** Different (state, action) pairs often lead to **the same afterstate** — several move orders reach an identical position. $Q(s,a)$ treats these as unrelated entries and must learn each separately; $V(\text{afterstate})$ learns them **once**. Transpositions are extremely common in chess and checkers, so the saving is large.
>
> **3. It matches how humans evaluate.** A player judges the *position* that results, not the move-position pair.
>
> **Why it fails for stochastic games** — and backgammon is the instructive case. With dice, $\text{succ}(s,a)$ is not a single state but a distribution over 21 possible rolls. TD-Gammon handles this by evaluating the afterstate *before* the dice are rolled, then averaging over rolls — still using $V$, but requiring an explicit expectation.
>
> **The general principle:** *"$Q$ is necessary when you lack a model"*. Games always come with a perfect model, so the model-free constraint of Lectures 4–5 simply does not bind here.

**3.** Explain the progression TD Root → TD Leaf → TreeStrap, and why chess needed it when backgammon did not.

> [!example]- Solution
> **The problem.** Simple TD gives superhuman play in Othello and Backgammon but **poor performance in Chess and Checkers**. The lecture's diagnosis: *"in chess tactics seem necessary to find signal in a position — e.g. hard to find checkmates without search."*
>
> **Why the games differ.** In backgammon, a position's static features (checker distribution, blots, pip count) genuinely predict the outcome — the game is smooth and probabilistic, and the dice blur tactical detail away. In chess a position can look quiet and be lost to a forced mate in four. **The static evaluation is not merely inaccurate but qualitatively wrong**, and only search reveals the truth. So learning from static successor values learns from a corrupted signal.
>
> **The three answers, each extracting more from the search:**
>
> **TD Root (Samuel, 1959).** Update the root's value toward the *search* value of the successor: $v(S_t) \leftarrow v_+(S_{t+1})$. The target is now search-informed rather than static. But the *update* still applies at the root, which the search never directly evaluated.
>
> **TD Leaf.** Update the **leaf that the search relied on**: $v(l_+(S_t)) \leftarrow v(l_+(S_{t+1}))$. Since minimax's root value *is* a leaf's value, the error belongs at that leaf. **KnightCap reached master level after a small number of games** — but *"was not effective in self-play"* and *"was not effective without starting"* from sensible piece values. Both limitations come from data scarcity: one update per move is little signal, so it needs a strong opponent and a good prior.
>
> **TreeStrap.** Update **every node** in the tree toward its own deeper search value: $v(s) \leftarrow v_+(s)$ for all $s\in\text{nodes}(S_t)$. A single move's alpha-beta search visits millions of nodes, and **every one becomes a training example**.
>
> **That volume is why Meep succeeds where KnightCap failed.** With thousands of updates per move instead of one, Meep is *"effective in self-play"* and *"effective from random initial weights"* — it can bootstrap knowledge from nothing, and won **13/15 against international masters**.
>
> **The unifying idea is bootstrapping from a better estimate of the same quantity** — the TD principle of [[04 - Model-Free Prediction]]. Here the "better estimate" is not one step later in time but **deeper in the search tree**. Deeper search is more accurate, so it makes a legitimate target, and TreeStrap simply harvests every such target the search produces.

**4.** TD-Gammon used **no exploration** and converged despite the deadly triad. Explain both.

> [!example]- Solution
> **No exploration.** TD-Gammon used *"greedy policy improvement (no exploration)"* — which directly contradicts [[05 - Model-Free Control]]'s GLIE requirement and [[09 - Exploration and Exploitation]]'s entire argument. Greedy action selection should lock onto suboptimal actions and suffer linear regret.
>
> **Backgammon's dice explore for it.** Every turn begins with a random roll from 21 equally likely outcomes, which **forces the game into positions the agent would never choose to visit**. The environment injects stochasticity that no policy can suppress, so state coverage is guaranteed regardless of how greedy the policy is.
>
> This makes explicit what $\epsilon$-greedy is *for*: ensuring adequate state visitation. When the environment already provides it, the mechanism is redundant. **The lecture's warning — *"not true for other games"* — is the flip side:** chess is deterministic, so a greedy self-play agent can play the same line forever and never see anything else.
>
> **Convergence despite the deadly triad.** TD-Gammon has **function approximation** (a neural network — non-linear), **bootstrapping** (TD(0)), and self-play, which is at least off-policy-flavoured. [[06 - Value Function Approximation]]'s table says non-linear TD is **✗**, and it can diverge.
>
> Yet *"the algorithm always converged in practice."* Several factors plausibly help:
> - **The dice again** — stochastic transitions smooth the value function and average away the sharp local structure that destabilises approximation. Backgammon's $v_*$ is genuinely smooth in the features.
> - **On-policy, self-consistent state distribution.** Self-play visits states in the proportions the policy actually induces, which removes the off-policy leg that Baird's counterexample exploits.
> - **A well-matched representation.** Backgammon's features (checker counts per point) map naturally onto its value function.
>
> **The honest lesson is the caveat, not the success.** The deadly triad describes what *can* happen, not what always does. TD-Gammon is an existence proof that the combination sometimes works spectacularly — and the explicit *"not true for other games"* is the reminder that it is luck of the domain, not a general guarantee. **Deep RL spent the next twenty years building the machinery ([[06 - Value Function Approximation]]'s replay and fixed targets) needed where that luck runs out.**

**5.** (Advanced) Explain how imperfect-information games differ, and what Smooth UCT's use of *average* behaviour accomplishes.

> [!example]- Solution
> **The structural difference:** *"players have different information states and therefore separate search trees."* In chess both players see the same board, so there is one game tree. In poker I see my cards and not yours, so **we are searching different trees** — and a node is not a game state but an **information state**, summarising what a player knows. *"Many real states may share the same information state."*
>
> This is the POMDP situation of [[01 - Introduction to Reinforcement Learning]] and the aliasing of [[07 - Policy Gradient Methods]]: two genuinely different situations (you hold aces / you hold rags) look identical to me. Three consequences follow:
>
> **1. Minimax breaks down.** $\max_{\pi^1}\min_{\pi^2}$ presumes each player can evaluate positions. With hidden information there is no single position to evaluate — only a distribution over them, and that distribution **depends on the opponent's strategy** (which hands they would have played this way).
>
> **2. Optimal play must be stochastic.** A deterministic poker policy is exploitable — always bluffing or never bluffing is read immediately. The Nash equilibrium is a **mixed** strategy, which value-based greedy methods cannot represent at all.
>
> **3. Beliefs are strategy-dependent.** My estimate of your hand is derived from your betting, which depends on your policy. So evaluation and opponent modelling are entangled in a way they never are in chess.
>
> **What Smooth UCT does.** It applies MCTS to the information-state tree, but with a twist *"inspired by game-theoretic Fictitious Play"*: **agents learn against and respond to opponents' *average* behaviour**, extracting the average strategy from visit counts, $\pi_{avg}(a\mid s) = N(s,a)/N(s)$. At each node it mixes UCT selection with sampling from $\pi_{avg}$.
>
> **Why averaging matters — it prevents cycling.** Best-responding to the opponent's *current* policy is unstable: I adapt, you adapt to my adaptation, I adapt back, and the pair can oscillate forever without approaching equilibrium. Rock-paper-scissors is the minimal example, and the lecture's framing of Nash as a *fixed point of self-play* quietly assumes a fixed point is reached.
>
> **Fictitious Play's classical result is that best-responding to the opponent's *historical average* converges to Nash in zero-sum games.** Smooth UCT imports that guarantee into MCTS. Averaging also **produces a mixed strategy for free** — the visit-count distribution *is* a stochastic policy, which is exactly what an equilibrium requires.
>
> **The results confirm the difficulty:** counterfactual regret minimization achieved *"'perfect' play"* in heads-up limit Hold'em, while Smooth UCT earned *"3 silver medals"* — strong, not dominant. **Imperfect information remains genuinely harder than perfect information**, which is why heads-up limit Hold'em was solved two decades after chess.

## 📝 Summary

- **Games are the drosophila of AI** — simple rules, deep concepts, meaningful benchmarks.
- **Fixing the opponents reduces a game to an MDP**; the **best response** is that MDP's optimal policy. **Nash equilibrium is the fixed point of self-play RL.**
- **Two-player zero-sum:** $R^1 + R^2 = 0$; solved by **game-tree search** or **self-play RL**.
- **Minimax:** $v_*(s) = \max_{\pi^1}\min_{\pi^2}v_\pi(s)$, found by depth-first search with a **value function approximator at the leaves** because the tree grows exponentially.
- **Deep Blue and Chinook used hand-tuned binary-linear weights** plus massive alpha-beta search.
- **Afterstates let deterministic games use $V$ instead of $Q$** — the rules supply the model, so the table is $|\mathcal{A}|$× smaller and transpositions generalise.
- **Self-play TD:** **Logistello** (MC + GPI, 1.5M constructed features) and **TD-Gammon** (neural network, TD(λ), random init, **no exploration**) both reached superhuman play.
- **Simple TD fails in chess and checkers** because tactics require search to reveal a position's value.
- **TD Root → TD Leaf → TreeStrap** extract progressively more from the search: root value, then the leaf the search used, then **every node in the tree**. TreeStrap's volume is why **Meep works from random weights and in self-play** where KnightCap could not.
- **UCT = MCTS + UCB** and is the best method in Go, Hex, Lines of Action, Amazons; simple MC search suffices for Scrabble and Backgammon.
- **Imperfect information gives each player a separate information-state tree**, requires stochastic policies, and is solved by **counterfactual regret minimization** or **Smooth UCT**, which responds to the opponent's **average** behaviour.
- **The recipe:** binary features → linear or neural value function → a TD variant → self-play → search at decision time.

## ⚠️ Important Notes

**Self-play need not converge.** Nash is the *fixed point*, but best-responding to a moving target can cycle indefinitely. Averaging (Fictitious Play, Smooth UCT) is what stabilises it.

**Afterstates work only when the model is known.** Games always supply it; general RL does not, which is why [[05 - Model-Free Control]]'s insistence on $Q$ still holds outside games.

**In stochastic games the afterstate is a distribution.** Backgammon evaluates before the dice roll, then averages over 21 outcomes.

**TD-Gammon's "no exploration" is a property of backgammon, not of RL.** Dice provide forced state coverage; deterministic games have no such luck, and greedy self-play there can visit almost nothing.

**TD-Gammon's convergence under the deadly triad is domain luck, not a general result.** The lecture says so explicitly: *"not true for other games."*

**Simple TD fails where static evaluation is qualitatively wrong.** A quiet-looking chess position can be lost to a forced mate — no amount of feature engineering fixes learning from a corrupted target.

**TreeStrap's advantage is data volume.** One search visits millions of nodes; using all of them as training examples is what lets Meep learn from random initial weights.

**KnightCap's failure modes are instructive:** ineffective in self-play, and ineffective without good starting weights. Both trace to one update per move.

**Deterministic optimal policies are exploitable in imperfect-information games.** Poker requires mixed strategies, so greedy value-based methods cannot represent the solution.

**Minimax presumes both players evaluate the same position.** With hidden information there is only a belief distribution, and it depends on the opponent's strategy — so evaluation and opponent modelling are entangled.

**Perfect play in heads-up limit Hold'em came two decades after Deep Blue.** Imperfect information is genuinely harder, not merely a variation.
